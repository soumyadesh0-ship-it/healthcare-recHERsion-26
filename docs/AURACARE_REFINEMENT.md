## Calendar rules

Calendar dates continue using the stored wall-clock year/month/day and declared timezone, preserving the application's existing behavior. No timezone migration or inferred day shifting is performed. The newest successful save supplies the day's flow and mood independently. Older entries without save metadata fall back to observation time with a deterministic ID tie-break. All entries remain available in the Timeline list. Entries without a recognized mood produce no mood border. Missing period intensity uses the neutral unspecified-period fill. No predictions or synthetic health records are generated by the app.

The existing repository stamps a record only after its write and version checks succeed. Save failures leave records and previous timestamps unchanged. JSON export retains its old fields and includes the two optional metadata fields when present. Health records remain session-only, as before this task.
